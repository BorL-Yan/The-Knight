# Game Design & Development Plan

## Мобильная браузерная версия 2D Roguelite-RPG

> Цель документа: превратить исходную идею в небольшой, понятный и
> реально выполнимый MVP для мобильного браузера. План специально
> упрощён: сначала создаётся одна игровая петля, затем добавляются
> контент и вариативность.

------------------------------------------------------------------------

# 1. Краткая концепция

Игрок выбирает одного героя и отправляется через телепортационный портал
в лесной мир.

Основная игровая петля:

**Исследование → клетка → событие → награда/бой → усиление → следующий
путь → босс**

Главная особенность:

**Игрок перемещается по небольшому полю свайпами, а в бою использует
последовательности свайпов V/H для активации магических атак.**

Где:

-   **V** --- вертикальный свайп: вверх или вниз.
-   **H** --- горизонтальный свайп: влево или вправо.
-   Последовательность свайпов является комбинацией способности.
-   Чем быстрее игрок вводит комбинацию, тем выше множитель атаки.
-   Бой должен занимать несколько секунд, а не превращаться в длинную
    RPG-битву.

------------------------------------------------------------------------

# 2. Что оставить в первой версии

Не нужно сразу делать всю игру из идеи.

## MVP

Для первой версии достаточно:

1.  Главное меню.
2.  Выбор одного героя.
3.  Одна лесная карта.
4.  20--30 клеток.
5.  Перемещение героя по клеткам свайпом.
6.  3 типа обычных клеток:
    -   бой;
    -   награда;
    -   магазин.
7.  Один тип сундука + ключ.
8.  3 обычных врага.
9.  3 магические способности.
10. Один босс.
11. Простая система улучшений.
12. Смерть и начало нового забега.
13. Сохранение постоянной валюты между забегами.

Не делать в MVP:

-   несколько героев одновременно;
-   сложную экипировку;
-   большой инвентарь;
-   десятки ресурсов;
-   процедурную генерацию огромного мира;
-   сложные диалоги;
-   сложную физику;
-   online;
-   PvP;
-   сложный AI.

# 3. Целевая платформа

## Мобильный браузер

Основной формат:

-   portrait;
-   управление одним пальцем;
-   большие интерактивные элементы;
-   минимальное количество текста;
-   короткие игровые сессии;
-   экран должен хорошо работать примерно от 360×640 и выше.

Рекомендуемый основной дизайн-размер:

**1080 × 1920**

При этом UI не должен зависеть от конкретного разрешения.

В Unity:

-   Canvas Scaler → Scale With Screen Size;
-   Reference Resolution → 1080 × 1920;
-   Match → около 0.5;
-   важные кнопки располагать внутри Safe Area.

------------------------------------------------------------------------

# 4. Основной игровой цикл

Один забег должен выглядеть так:

``` text
Главное меню
    ↓
Выбор героя
    ↓
Лесная карта
    ↓
Свайп
    ↓
Переход на соседнюю клетку
    ↓
Событие клетки
    ├── Пустая клетка
    ├── Бой
    ├── Сундук
    ├── Ключ
    ├── Магазин
    └── Босс
    ↓
Награда / усиление
    ↓
Следующая клетка
    ↓
Босс
    ↓
Победа / смерть
    ↓
Постоянная награда
    ↓
Новый забег
```

Главное правило:

**Игрок всегда должен понимать, зачем ему двигаться дальше.**

------------------------------------------------------------------------

# 5. Карта

## Размер MVP

Не использовать огромную карту.

Сделать:

**8 колонок × 12--15 строк**

На экране одновременно показывать примерно 5--7 клеток по ширине карты в
зависимости от масштаба.

Карта может прокручиваться вертикально.

------------------------------------------------------------------------

## Типы клеток

Минимальный набор:

  Тип        Назначение
  ---------- ------------------------
  Empty      Безопасное перемещение
  Enemy      Бой
  Chest      Сундук
  Key        Ключ
  Merchant   Магазин
  Shrine     Усиление
  Boss       Главный враг

Каждая клетка --- обычный prefab.

Например:

``` text
Cell
 ├── Background
 ├── Icon
 ├── Lock
 └── Highlight
```

Не создавать сложную систему комнат на первом этапе.

------------------------------------------------------------------------

# 6. Перемещение по карте

Управление --- свайп.

Игрок делает:

-   свайп вверх → перейти на клетку выше;
-   свайп вниз → перейти на клетку ниже;
-   свайп влево → перейти влево;
-   свайп вправо → перейти вправо.

Герой перемещается **ровно на одну клетку**.

## Логика

``` text
Touch Down
    ↓
Запоминаем позицию
    ↓
Touch Up
    ↓
Считаем delta
    ↓
Если delta X > delta Y
    → Horizontal
иначе
    → Vertical
    ↓
Определяем направление
    ↓
Проверяем соседнюю клетку
    ↓
Перемещаем игрока
    ↓
Активируем событие клетки
```

Для MVP лучше использовать именно такую простую систему вместо сложной
навигации.

------------------------------------------------------------------------

# 7. Почему клеточное движение подходит игре

Клетка решает сразу несколько проблем:

-   игрок легко понимает направление;
-   можно строить маршруты;
-   удобно делать случайные события;
-   легко показывать карту на мобильном экране;
-   легко контролировать сложность;
-   можно делать короткие игровые решения.

Главное --- визуально не превращать игру в классическую шахматную сетку.

Клетки должны выглядеть как части леса:

``` text
┌─────┐
│ 🌲  │
│  •  │
└─────┘
```

Границы клеток лучше делать визуально мягкими.

------------------------------------------------------------------------

# 8. Боевая система

Бой начинается сразу после входа на клетку врага.

Клетка превращается в небольшую боевую сцену.

Экран:

``` text
┌──────────────────────┐
│ ❤️ HP       Enemy HP │
│                      │
│      ENEMY           │
│                      │
│       HERO           │
│                      │
├──────────────────────┤
│ Combo: ↑ → ↓         │
│                      │
│   [ Swipe Area ]      │
│                      │
│  Skill  Skill  Skill │
└──────────────────────┘
```

Не нужно делать отдельный сложный экран загрузки.

Переход должен быть быстрым:

**карта → бой → карта**

------------------------------------------------------------------------

# 9. Комбинации магии

Это центральная механика игры.

Каждая способность имеет комбинацию:

``` text
Fireball
↑ → ↓

Lightning
→ → ↑

Ice
↓ ← ↑
```

Игрок выполняет последовательность свайпов.

После каждого правильного направления:

-   показывается символ;
-   появляется маленький эффект;
-   шкала combo заполняется.

После полного совпадения:

**атака активируется.**

------------------------------------------------------------------------

# 10. Ошибка в комбинации

Не наказывать игрока слишком сильно.

Если игрок сделал неправильный свайп:

``` text
Combo reset
↓
небольшая потеря времени
↓
можно попробовать снова
```

Не нужно отправлять игрока сразу в проигрыш.

Цель системы --- создать удовольствие от быстрого ввода.

------------------------------------------------------------------------

# 11. Скорость ввода

Это главный источник Atomic Pleasure.

У каждой комбинации есть:

``` text
Base Damage = 100

Normal:
x1.0

Fast:
x1.2

Very Fast:
x1.4
```

Для MVP достаточно трёх уровней.

Например:

``` text
↑ → ↓
```

Игрок вводит быстро:

``` text
↑ → ↓
      ↓
Attack ×1.4
```

На экране нужно крупно показать:

**PERFECT ×1.4**

Это должно быть визуально приятнее, чем просто увеличение цифры.

------------------------------------------------------------------------

# 12. Как сделать быстрый ввод приятным

Каждый правильный свайп должен давать мгновенную обратную связь:

1.  короткий звук;
2.  маленькая вспышка;
3.  символ направления;
4.  увеличение combo;
5.  лёгкое движение UI;
6.  финальный эффект способности.

Например:

``` text
Swipe ↑
   ↓
CLICK
   ↓
↑ появляется на экране
   ↓
маленькая вспышка
   ↓
Swipe →
   ↓
CLICK
   ↓
↑ →
   ↓
Swipe ↓
   ↓
MAGIC!
   ↓
×1.4
   ↓
ATTACK
```

Это важнее большого количества контента.

------------------------------------------------------------------------

# 13. Система способностей

Для MVP сделать 3 способности.

## Fire

Комбинация:

``` text
↑ → ↓
```

Эффект:

-   огненный удар;
-   средний урон.

## Ice

Комбинация:

``` text
↓ ← ↑
```

Эффект:

-   средний урон;
-   замедление врага.

## Lightning

Комбинация:

``` text
→ → ↑
```

Эффект:

-   высокий урон;
-   более длинный cooldown.

------------------------------------------------------------------------

# 14. Почему лучше 3 способности

Не нужно делать 20 заклинаний.

Игрок должен сначала научиться:

``` text
узнавать комбинацию
        ↓
запоминать
        ↓
быстро вводить
        ↓
получать ×1.4
```

После этого можно добавлять новые способности.

------------------------------------------------------------------------

# 15. Враги

В MVP достаточно трёх типов.

## 1. Обычный враг

-   средний HP;
-   простой удар;
-   медленная атака.

## 2. Быстрый враг

-   мало HP;
-   быстро атакует;
-   требует быстрого уничтожения.

## 3. Танк

-   много HP;
-   медленно атакует;
-   лучше использовать сильную способность.

------------------------------------------------------------------------

# 16. Приоритет целей

В бою может быть 2--3 врага.

Игрок должен выбрать, кого уничтожить первым.

Принцип:

``` text
Опасный враг
     ↓
Убить первым?

или

Слабый враг
     ↓
Быстро убрать?

или

Танк
     ↓
Оставить на потом?
```

Это создаёт маленькую стратегию без сложной RPG-системы.

------------------------------------------------------------------------

# 17. Автоматическая атака врагов

Чтобы игра не стала сложной:

-   враги сами атакуют по таймеру;
-   игрок не управляет каждым ударом;
-   игрок управляет только выбором цели и использованием магии.

Например:

``` text
Enemy attack timer = 2 sec
```

Игрок должен успеть выполнить комбинацию до следующей атаки.

------------------------------------------------------------------------

# 18. Сундук и ключ

Это второй мини-гейм.

На карте:

``` text
[Chest]
```

В другом месте:

``` text
[Key]
```

Игрок должен решить:

**сначала искать ключ или идти дальше?**

После получения ключа:

``` text
Key → Chest
```

Сундук открывается.

Награда:

-   GCoins;
-   магический камень;
-   новое заклинание;
-   временный бонус.

Для MVP достаточно одного типа ключа.

------------------------------------------------------------------------

# 19. Магазин

Встречается на карте.

Простой экран:

``` text
┌────────────────────┐
│      MERCHANT      │
├────────────────────┤
│ 🔥 Fire +20%       │
│      40 Coins      │
├────────────────────┤
│ ❤️ Max HP +20      │
│      30 Coins      │
├────────────────────┤
│ ⚡ Combo Time +20%  │
│      50 Coins      │
└────────────────────┘
```

Не делать инвентарь.

Покупка сразу применяется к герою.

# 20. Улучшения

В MVP только 5 параметров:

``` text
Max HP
Base Damage
Magic Damage
Combo Time
Move Speed
```

Но игроку лучше показывать их понятными словами:

-   ❤️ Здоровье
-   ⚔️ Урон
-   ✨ Магия
-   ⚡ Скорость комбинации
-   👟 Скорость движения

# 21. Постоянный прогресс

После смерти игрок теряет временные усиления.

Но получает постоянную валюту.

``` text
Run
 ↓
Death
 ↓
Получили Magic Stones
 ↓
Permanent Upgrade
 ↓
New Run
```

Это создаёт roguelite-петлю.

------------------------------------------------------------------------

# 22. Система прогрессии

Не делать большое дерево навыков.

Для MVP:

``` text
Magic Stone

├── +10 Max HP
├── +5% Damage
├── +5% Combo Speed
└── +5% Starting Coins
```

Игрок покупает улучшения постепенно.

------------------------------------------------------------------------

# 23. Босс

В конце карты находится главный монстр.

Босс должен отличаться от обычных врагов не количеством HP, а
поведением.

Например:

### Phase 1

Обычные атаки.

### Phase 2

Босс создаёт опасные зоны.

### Phase 3

Босс ускоряется.

Но для первого прототипа можно сделать только:

**большой HP + 2 атаки + уязвимость после атаки.**

------------------------------------------------------------------------

# 24. Победа

После смерти босса:

``` text
BOSS DEFEATED
        ↓
Reward
        ↓
Run Complete
        ↓
Permanent Upgrade
        ↓
New Run
```

Не нужно делать длинную концовку.

------------------------------------------------------------------------

# 25. Поражение

Игрок проигрывает если:

-   HP героя = 0;
-   герой попал в смертельное событие;
-   проиграл боссу.

После смерти:

``` text
DEFEAT

Magic Stones +25

[Continue]
```

И затем:

**новый забег.**

------------------------------------------------------------------------

# 26. Визуальный стиль

Главная проблема концепции --- не механика, а визуальная подача.

Не обязательно использовать пиксель-арт.

Для мобильного браузера рекомендован:

**Stylized 2D / Cartoon Fantasy**

Основные принципы:

-   простые формы;
-   толстые силуэты;
-   минимум мелких деталей;
-   яркие эффекты;
-   контрастный персонаж;
-   спокойный фон;
-   крупные интерактивные объекты.

------------------------------------------------------------------------

# 27. Рекомендованный визуальный pipeline

``` text
256–512 px
```

Не делать уникальный огромный фон для каждой клетки.

# 33. Система комбинаций

Лучше хранить комбинацию как массив enum:

``` csharp
public enum SwipeDirection
{
    Up,
    Down,
    Left,
    Right
}
```

Способность:

``` text
Ability
 ├── Name
 ├── Damage
 ├── Cooldown
 ├── Combo
 └── Effect
```

Пример:

``` text
Fireball
Damage = 30
Combo = [Up, Right, Down]
```

------------------------------------------------------------------------

# 34. Проверка комбинации

Логика:

``` text
Player Swipe
      ↓
Current Ability
      ↓
Expected Direction
      ↓
Correct?
 ├── YES → next input
 └── NO  → combo reset
      ↓
All inputs correct?
 ├── NO → wait
 └── YES
      ↓
Calculate Speed Bonus
      ↓
Attack
```

------------------------------------------------------------------------

# 35. Расчёт множителя

Не нужно делать сложную формулу.

Например:

``` text
time <= 0.8 sec → x1.4
time <= 1.5 sec → x1.2
time > 1.5 sec  → x1.0
```

Формула:

``` text
Final Damage = Base Damage × Multiplier
```

Пример:

``` text
Base Damage = 50
Multiplier = 1.4

50 × 1.4 = 70
```

------------------------------------------------------------------------

# 36. Переиспользование контента

Чтобы разработка была быстрой:

### 1 Enemy prefab

Меняются:

-   HP;
-   damage;
-   speed;
-   sprite;
-   attack interval.

### 1 Cell prefab

Меняется:

-   CellType;
-   icon;
-   event.

### 1 Ability prefab

Меняются:

-   combo;
-   damage;
-   effect.

Таким образом, новые элементы создаются в основном через данные, а не
через новый код.

# 43. Playtest


# 45. Browser Performance

Для мобильного браузера:

-   использовать небольшое количество объектов;
-   использовать Sprite Atlas;
-   избегать большого количества прозрачных слоёв;
-   не делать тяжёлые пост-эффекты;
-   ограничить количество частиц;
-   использовать object pooling для повторяющихся VFX;
-   минимизировать GC allocations во время боя;
-   не создавать/удалять UI объекты постоянно;
-   использовать простые 2D материалы.

Целевая идея:

**игра должна стабильно работать на слабом Android, а не только на
современном телефоне.**
